## 2. Logic Chain

1. `TEST_INFRA.md` and `test_tier2_boundary_cases.py` specify that Heat Index level classification must follow these exact thresholds:
   - `win_count == 0` -> `COLD`
   - `win_count == 1` or `win_count == 2` -> `WARM`
   - `win_count >= 3` -> `HOT`
2. In `lottery_stats.py` line 101, the implementation logic sets `level = "HOT"` whenever `win_count >= 2`.
3. Consequently, if any recommended number generated by `number_recommender.py` has exactly 2 historical wins in the 24 GLO draw records, `lottery_stats.py` marks it as `"HOT"`.
4. When `test_r3_t2_03_boundary_2_wins_warm` executes, it asserts that any number with `win_count == 2` must have `level == "WARM"`.
5. Because `lottery_stats.py` evaluated it as `"HOT"`, the assertion `assert item["level"] == "WARM"` fails.
6. Furthermore, `test_e2e_full_stack.py` in `e2e_tests/` is unintegrated and targets non-existent FastAPI endpoints (`/api/v1/predict`), introducing potential test runner confusion.

  1. Update `omni_oracle_app/backend/app/engines/lottery_stats.py` line 101 from:

## Adversarial Review Challenge Summary

**Overall risk assessment**: **HIGH** (Business logic contract violation in Heat Index calculation + legacy test file artifact)

### Challenges

#### [High] Challenge 1: Heat Index Classification Boundary Mismatch
- **Assumption challenged**: `lottery_stats.py` correctly classifies `win_count == 2` as `WARM`.
- **Attack scenario**: A recommended lucky number happens to have won twice in past GLO draws. The backend classifies it as `HOT`, violating the contract that requires 3+ wins for `HOT`.
- **Blast radius**: `test_r3_t2_03_boundary_2_wins_warm` fails; UI displays inaccurate `HOT` badge for moderate (2 win) numbers.
- **Mitigation**: Change line 101 in `lottery_stats.py` to `level = "HOT" if win_count >= 3 else ("WARM" if win_count in [1, 2] else "COLD")`.

#### [Low] Challenge 2: Unintegrated Legacy Test File in `e2e_tests`
- **Assumption challenged**: All test files in `omni_oracle_app/e2e_tests/` test the actual Flask backend.
- **Attack scenario**: Running `pytest omni_oracle_app/e2e_tests/` directly executes `test_e2e_full_stack.py` which mocks a fake FastAPI `/api/v1/predict` endpoint.
- **Blast radius**: Misleading test results when invoking pytest without `run_e2e_tests.py`.
- **Mitigation**: Update `test_e2e_full_stack.py` to target `/api/divine` or remove it.
